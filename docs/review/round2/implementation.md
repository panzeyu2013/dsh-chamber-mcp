## Verified answers to the round-2 deep-dives

(a) **Epoch correctness** — sound. `nextEpoch` (`manager.ts:91-95`) bumps per `startServer`; each handle's `onDefsChanged` closure captures its own start epoch (`:127-135`), so all commits of one handle — including its give-up empty push (`server.ts:290-295`) — carry one token. Pushes are strictly ordered per name: old-handle commits cannot land after `tracked.delete` because (i) `stopServer`'s synchronous prefix (`revokeServer`/`tracked.delete` → `handle.dispose()`'s `disposed=true` prefix, `:142-152`) is one await-free block, so no commit microtask interleaves; (ii) `enqueueSync`'s `isCurrent` checks (`server.ts:240-243`) and dispose's `await settling`/`await syncChain` (`:427-428`) quiesce late commits; (iii) stop/start serialize on the mutation chain. An `(epoch+1, syncId=0)` give-up push therefore can only arrive when the old handle is fully quiesced — no transient race with an in-flight old-handle generation swap. `applyToEntry` with `state.defs` empty + `applied` under an older epoch revokes correctly: `enabled` is false → revoke with reason `'server has no tools'` (`agents.ts:222-232`) — the disabled branch runs before the `(epoch,syncId)` guard, so even an EMPTY push carrying the *same* syncId as the applied generation revokes (this is exactly the give-up case). Logs/reasons are correct in all four revoke reasons (`:224-231,274,298`). Mutation experiment confirms the guard's epoch half is load-bearing (test fails when removed). One nit: `epochs` is never pruned on stop — bounded, meaningless growth.

(b) **pushServerState / reconcile refresh ordering** — correct. `pushServerState` sets state, then `refreshEntryWorkspaces()` (ONE registry snapshot), then applies (`agents.ts:261-268`); `reconcile` refreshes once and reads `overrides()` once for the whole loop (`:284-288`) — no N-calls, no re-read per (entry × server) pair. All three phases are synchronous, so "entries added between refresh and push" cannot occur on the JS thread; `adopt` resolves its own fresh snapshot at adopt-time (`:153-154,177`) and later events refresh it again. Entries adopted mid-life are applied from current `serverState` at adopt (`:183`) and re-judged by every subsequent push/reconcile.

(c) **Subagent filter + roots** — a `'subagent'`-origin agent cannot be in `agents.roots()` (roots = top-level agents only, per dsh-agent d.ts), and the filter in `adopt` handles it anyway; both adoption paths are symmetric through `adopt`. Double-adopt (agent/created while a roots scan already adopted it) is guarded by `entries.has` (`agents.ts:169`) and impossible to interleave anyway (listeners + scan in one synchronous effect block). Agent/created for an already-adopted agent → early return.

(d) **Transport CRLF/NUL rejection** — warn lines name ref/header only, never the value (`transport.ts:77-80,107-110`; asserted not to contain `\r\n\0` or the values, `transport.spec.ts:116-155`). All-keys-rejected → empty env/headers are fine (`{}` flows into `buildChildEnv`/`requestInit.headers`). Re-resolution on reconnect happens per attempt through `buildTransport` (`manager.ts:130`), so a fixed credential is picked up on the next attempt; a persistently invalid value re-warns once per attempt, bounded by `maxAttempts`. No resolved value reaches any other log path (spawn/Headers errors occur only after rejection).

(e) **New-test quality** — read line by line; none is vacuous, and each fails if its fix is reverted:
epoch/restart test (`agents.spec.ts:350-387`) fails without the epoch guard (proven by mutation); no-op-reconcile test (`:389-425`) fails if any force pass returns (log-count + definition identity); deletion-revoke (`:427-450`) and creation-after-adopt (`:452-470`) fail if `refreshEntryWorkspaces` is dropped (stale workspaceId would keep/withhold tools); subagent-skip (`:472-517`) fails if the filter is removed (tracking line + visibility assertions) and cannot pass vacuously because the root is asserted adopted in the same test; coalescing (`manager.spec.ts:165-204`) fails without the absorber (2 "reconnecting" lines) and without marker clearing (third event wouldn't restart); CRLF tests (`transport.spec.ts:116-155`) fail without the rejection; give-up test (`server.spec.ts:186-215`) fails if counters/log return (generation/syncId must stay 0, no "synced 0 tools", exact single commit). Minor harness caveat: the pre-existing-adoption test's second applier coexists with the first in one agent scope, but only one of them ever registers a given name in that test, so no register-conflict cross-talk occurs.

(f) **Fix-round leftovers** — no TODO/FIXME; no stale in-code comments found in `agents/manager/server/transport.ts` (epoch, unregister, and refresh comments all match behavior). Leftovers: unused `startup` param (`server.ts:314`), unused `isEnabled` import (`controller.ts:28`) — R2I-6; stale host-notes — R2I-5; the old give-up/agentViews/`ready.then` artifacts are gone. All existing tests reflect the new semantics (give-up test updated; harness uses the epoch-carrying `push` signature throughout).

(g) **Flakiness** — 3 full runs + 5 host-only runs + 1 post-experiment run: zero flakes. The only wall-clock-dependent assertions are the "quiet after dispose" 100–150 ms windows and the coalescing quiet windows; with shrunk reconnect timers (maxDelay 20–500 ms) they proved stable across all runs.

## Fidelity-diff list (changes vs official contract, §3–4 recon)

1. **Give-up path (changed this round)** — official (`ref connection.ts:210-215`) enqueues disposer disposal and logs `giving up after N consecutive failed reconnect attempts — tools unregistered; reload the plugin or restart the Host to reconnect`; ours enqueues the same error text plus `unregister()` (EMPTY push, no sync log/counter) on the sync chain — the push is the architectural requirement of the decoupled agent gate (deviation D8/D9; now implemented without the IMPL-4 residue). Fidelity of reconnect math, close discipline, budget reset, and disable-branch wording re-verified unchanged (`server.ts:273-306` vs ref `connection.ts:192-225`).
2. **Give-up log ordering nuance** (new, cosmetic): ours logs the give-up error inside the chain closure after a `disposed` check (`server.ts:291-292`); official logs it unconditionally at decision time. If dispose lands between the decision and the closure, ours suppresses the line (and skips the push, which the manager's own revocation covers). Not a semantic regression; logging-only.
3. **Transport boundary (changed this round)** — CR/LF/NUL value rejection has no official counterpart because official env/header values are plain config strings (D7 already deviated to credential-sourced values); the rejection is a net-new defense, cannot violate wire parity.
4. **Manager/applier epochs + coalescing + refresh (new this round)** — no official counterpart (official has no per-agent gate, no restart-on-doc-change, no settings bridge); verified internally consistent (see (a)-(c)).
5. **Subagent exclusion** — documented deviation (agents.ts header, acceptance.md, SUMMARY) vs official global registration; consistent both adoption paths.
6. **Docs drift (not fixed)** — host-notes §c6 contradicts current code (R2I-5); round-1 doc `implementation.md` D9 text ("give-up = commit(EMPTY_DEFS) (counter/log side effects — see IMPL-4)") describes pre-fix behavior — historical, but should be flagged when that file is next touched.
7. Everything else that the fix round did not touch (naming contract, executor semantics, pagination, reconnect math, scrub+merge env, wire identity, image-bridge cut) re-verified unchanged against `ref-dsh` and the recon §3–4 mirror.
