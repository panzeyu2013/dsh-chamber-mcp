## (a) Verdict

**The round-1 majors are fixed and the fix round's mechanism changes are sound — verified
against the real rc.1 artifact, not just the tests.** ARCH-1 (declared runtime imports), ARCH-2
(live workspace re-resolution), ARCH-3 (delegation-child exclusion) and ARCH-5 (diffed
reconcile) are all genuinely fixed; ARCH-3 in particular is now backed by anchor evidence that
was missing in round 1: in rc.1, `session.header.origin` is a literal `'subagent'` stamped **only**
by `dsh-subagent`'s `childSessionMeta` (`lib/index.js:659-670`, used by both the in-process
one-shot driver `dsh-subagent-in-process-driver/lib/index.js:182` and the continuation resume
path `dsh-subagent/lib/index.js:1505-1513`), while every root route — gateway/web session
create (`dsh-api-session-controller/lib/index.js:445`, meta `{cwd}` only), fork create
(`:695-700`, adds `parentSession`/`isSeeded`, no origin), ACP top-level (`dsh-acp/lib/index.js:694`)
— leaves origin absent. So the predicate `origin === 'subagent'` (agents.ts:174) is *exactly*
the delegation marker, both adoption paths are symmetric (single `adopt()` funnel), and children
never receive a registration in their own scope layer, which is the only layer rc.1
`restrict()` cannot narrow (anchor dsh-tools d.ts: "Restrictions … do not affect scoped
registrations", `lib/types/index.d.ts:472-473,604-606`). The epoch-based idempotence key,
restart coalescing, and the supervisor give-up push were walked microtask-by-microtask against
the teardown/quiescence discipline: **no stale-handle push can clobber a newer generation, and
no restart interleaving deadlocks or sticks** (details in §c R2A-0 walk). What keeps this from a
clean pass is a pile of *residual* items, none a re-opened major: (1) ARCH-2's tail — workspace
**delete** with live sessions still leaves tools registered until the *next* push/reconcile, and
rc.1's workspace registry exposes **no lifecycle events at all** (verified: no emit sites in
`dsh-workspace` lib), so in a quiescent host the window is unbounded — the mechanism is
documented ("on the next event", agents.ts:10-14) but the unbounded window itself is not called
out anywhere; (2) ARCH-7 (give-up revival on user settings commits) is **not fixed and has no
disposition row** in SUMMARY (matrix gap, corroborated by round2/fix-verification.md R2V-5);
(3) the fix round changed the code story but `docs/host-notes.md (c)6` still describes the
**pre-fix** reconcile (`with force`) — a factual doc regression — and `docs/design.md` still
carries the ARCH-1/ARCH-6 tails (§c R2A-2/3); (4) ARCH-9/11 ordering assumptions remain
unchanged and the full `apply()` path is still never exercised in-process. Severity of every new
finding: Low/Med — nothing above; the per-agent-scope injection gate remains the correct R3
mechanism and is now *demonstrated* rather than asserted at the mechanism level.

## (d) Fresh per-axis conclusions

**Axis 1 — Completeness vs locked scope.** R1-R4 claims stand as before, now with a stronger R3 mechanism story: the gate (per-agent-scope registration, never global) is unchanged and re-verified; workspace membership is live per push/reconcile with tests; delegation children are excluded by the *actual* rc.1 origin marker with both adoption paths symmetric. The acceptance contract "sessions outside any registered workspace get no MCP tools" still has a genuine runtime hole only in the workspace-*delete* case during quiescence (R2A-1) — the last remainder of round-1's ARCH-2 major, now bounded by event-driven recovery but unbounded in wall-clock time. ARCH-4's assembly-layer capture remains the one unproven R3 leg, and the m1 driver is leaving the closest reachable evidence (real-session applier lines) uncollected (R2A-6). ARCH-7 and ARCH-11 residuals are acknowledged-but-unrow'd in the disposition matrix (matrix gap also noted independently by fix-verification R2V-5).

**Axis 2 — Package/install model.** ARCH-1 is fixed: both undeclared runtime imports are now declared exactly where the official model declares them (zod dep at the official's range; dsh-timeout peer at the rc.1 range), so the boot-failure class is gone; the pack contains neither (declared, not bundled). No new packaging surface appeared in the fix round. The only leftover here is documentation (design.md §6 deps list, R2A-3) and the un-added LICENSE (fix-verification R2V-6, cross-cutting).

**Axis 3 — Module decomposition & data flow.** The decomposition survived the fix round intact and improved: manager owns epochs and restart coalescing; applier owns per-entry bookkeeping with one fresh workspace snapshot and one fresh doc snapshot per event; `(epoch, syncId)` dedupe is the right key given supervisors restart syncId at 1. The fresh finding is that *two* reconciles can disagree transiently (R2A-4, stale-doc resume after awaits) and only chain-order convergence saves the day — same class of implicit ordering invariant as ARCH-9/11; all three deserve comments or tests (R2A-4, R2A-7), not code surgery. Also note the residual that agent/created does not refresh *existing* entries (R2A-1 fix option 3) — a one-line change if workspace events stay unavailable.

**Axis 4 — Cordis effect/disposer discipline.** Unchanged from round 1 and re-walked: teardown LIFO (manager dispose effect registered after the applier/credential effects → runs first) with `disposed`/`isAlive` guards on every path; agent scope entries die with the agent ctx; disposers invoked only while the agent is alive; supervisor-level dispose quiescence is the load-bearing guarantee behind epoch safety. No regression found. The round-1 "revoke between scoped-unwind and agent/disposed" narrow residual is unchanged and still comment-worthy only.

**Axis 5 — Design optimality.** The four round-1 majors received the *right* fixes, judged against the anchor rather than the tests: origin-exclusion is strictly more precise than the round-1 alternative "adopt roots only" (it keys on the platform's own delegation marker, covering continuation-resumed children too, with zero new platform assumptions); re-resolution-per-event is the only viable membership strategy on rc.1 given the registry's silence (no events to subscribe to); diffed reconcile with a live enablement judgment is equivalent to tracking an applied enablement bit (round-1's suggestion) with less state. Remaining design-level debts are the same as round 1 minus the majors: mirror-maintenance on dsh bumps (epoch/workspace-event surfaces are exactly the kind of thing that changes between rc's — see Axis 6), force-less reconnect re-sync churn (acceptable), image-bridge wording (R2A-3), and the terminal-give-up affordance (ARCH-7).

**Axis 6 — Version/API surface risk.** All load-bearing rc.1 contracts re-checked this round against the installed artifact, including the new ones the fix round leaned on: `SessionHeader.origin` (`'subagent'|undefined`), the child-composition machinery (`composeFrom` + per-child `tools.restrict` at `dsh-subagent/lib/index.js:699-712`), `AgentRegistry.register/announce` scope-carrier emissions, per-agent `createScope(loopCtx, agent)` with no parent binding by default (`dsh-agent-loop/lib/index.js:381`), workspace `list()/delete()` with no events, `installSection` attach sequencing. The compile target is unchanged; no rc.2+ behavior was introduced. Forward risk list for the next bump: (1) if rc.5+ gains workspace lifecycle events or an origin vocabulary wider than `'subagent'`, the exclusion predicate and the membership residual (R2A-1) must be re-diffed; (2) epoch semantics depend on the supervisor-restart-syncId-reset property, which is internal to this plugin's own mirror — re-diff against the installed official client remains the standing discipline (round-1 Axis 6, unchanged).
