# Interaction/UX review — Round 2 (fix verification, `mcp-scope` settings section)

Reviewer: interaction/UX subagent (round 2). Verifies the round-1 findings
(`docs/review/interaction.md`, UX-01…19) against the **current** client code
and the jsdom suites, then reviews the new interactions for usability, copy
quality, and consistency with the official Settings patterns recorded in
`docs/recon/ui-contracts.md` §3–5. Every rendered string is cited by its
`mcp-scope.settings` locale key (`src/client/locales.ts`, en + zh mirrors,
key sets asserted equal by `tests/client/locales.spec.ts` and render spec #10).

**55/55 pass** — `section-render.spec.tsx` 10, `controller.spec.ts` 41,
`locales.spec.ts` 4. Source read in full: `section.tsx`, `server-card.tsx`,
`add-form.tsx`, `workspaces.ts`, `controller.ts`, `locales.ts`, `index.ts`;
both spec files. The `credentials/reference-updated` wire event name was

## Verdict

The round-1 **highs are genuinely addressed at the behavior level** and are
unit/render-pinned: per-surface `role="alert"` failures with a
`role="status"` success note + real focus move to the (programmatically
focusable) new/edited card header (UX-01), controller-level auto-cleanup of
newly-stored secrets on failure/refusal with landed-write verification
(UX-02), a real edit path with prefilled draft and rename-aware override
migration (UX-04), pluralized counts, dedicated row-button keys, a
configured/unset/**unknown** badge tri-state with event-driven retry, and
workspace-list loading/error gating — all pinned by 10 render tests that
assert user-visible text and focus targets.

However, the fix round leaves a **validation explain-dead-end** (an invalid
draft can never reveal its problems, R2U-01), **conflict copy that never
states "your change was not saved"** and hides the one un-restorable side
effect (overwritten pre-configured credentials keep the new literal, R2U-02),
**card-top-only error placement that stays off-screen for tall cards**
(R2U-03), incomplete **focus/dialog semantics on remove/cancel paths**
(R2U-04), and **draft-destroying card actions while a staged form is open**
(R2U-05). Copy is otherwise clean and the zh side is hand-quality, not
machine translation. Overall: **materially closer to release-grade than
round 1; interaction plumbing is right, the remaining problems are message
design and edge flows** — no data-integrity regression found in the new
flows beyond the documented shared-ref overwrite behavior.

## Round-2 targeted checks

- **(a) Conflict outcome — what does the user see?** The form/card shows the localized failure banner (`error.conflict`, per surface), the staged draft stays intact in the form, and the underlying doc is silently refreshed to the current state by `applyOps` → `refresh()` (`controller.ts:724`). Nothing in the copy states “your change did NOT apply / the list was reverted to the current state”, and the “changed elsewhere” wording is wrong for self-inflicted races (two quick toggles across cards). → R2U-02.
- **(b) New-secret cleanup after refusal.** Cleanup runs in `submitPlan` for every refusal/conflict path and ends in `unsetQuietly`, which calls `refreshCredentials()` after unsets (`controller.ts:689–699`), so badge state is re-derived. In practice no UNSET badge ever needs to flip: badges derive from doc refs and cleaned refs are by construction not in the doc (a failed add/edit's new refs). The add form keeps its typed draft (component state untouched on failure; the render test proves the form stays open with Save re-enabled, spec:342–363) → retry re-sends the literal. The cleanup is silent in the copy (no “value stored then removed” note), and pre-configured refs are never unset — their overwritten value persists (R2U-02). The cleanup-after-refusal event name used by the retry wiring matches the rc.1 runtime event list (verified in the anchor install).
- **(c) Rapid toggles / double-submit.** Pending state is per-card (`pendingWs`/`removing`/`clearingRef` in each `ServerCard`); within a card, all controls disable while one op is pending, plus re-entry guards in `handleClear`/`handleSave` — double-submit within a surface is blocked. Across cards, ops are *not* serialized: two quick toggles share a base revision and the second is fenced out → a conflict banner describing it as “changed elsewhere” (self-caused; see R2U-02). Retry then succeeds. Same-card same-row double-click cannot re-fire (checkbox disabled once pending renders).
- **(d) Empty/loading phases.** No flash: doc-level loading early-returns the section `state.loading` line (`section.tsx:103–105`); per-card rows show `workspaces.loading` while the list arrives and only show `workspaces.empty` when the list is settled with zero items (`server-card.tsx:285–295`); the off-chip/count is suppressed until settled. Render spec drives loading, error and settled-empty phases and asserts the absence of the empty text during load/error (spec:255–272).
- **(e) Locale.** Every new key exists in both dictionaries (compile-enforced + render spec #10); all fix-round strings verified en/zh — e.g. `secret.unknown` “Status unknown/状态未知”, `workspaces.loading` “Loading workspaces…/正在加载 workspace 列表…”, `add.added` “Added {name}/已添加 {name}”, `validation.refPattern` “Env-style name…/需为环境变量名：字母开头…”. zh is hand-quality throughout, no machine-translation awkwardness; nits: the 6-dot “……” ellipsis inside `mcp__……__*` (R2U-07), romanized “workspace” inside zh sentences (consistent with round-1 usage — glossary choice), and the reused “保存中…” on Clear (R2U-07).
- **(f) jsdom assertions.** They now assert user-visible behavior (banner text, alert counts, `activeElement` ids, phase strings, plural forms). Brittleness and blind spots: R2U-08 (fixed-timer flush, raw-English assertion, submit-event emulation bypassing the disabled gate, happy-order-only focus tests, no transient-dismissal/remove-focus coverage).

## Strengths (verified, not assumed)

- **aria-live semantics are now right**: failures `role="alert"` (assertive) per surface, success `role="status"` (polite) — no success ever shouts; no surface renders success and error simultaneously about the same action (the only overlap is a ≤8 s stale card failure sitting under a fresh success note — different subjects, benign).
- **Focus-after-add actually works**: the target is `tabIndex={-1}` (`server-card.tsx:182`), so programmatic focus and browser scroll-into-view function in the real renderer; the render spec pins the exact target element.
- **Cleanup engineering is careful and honest**: new-ref-only, best-effort, refusal-tolerant, never touches pre-configured values, runs after secret-write failure and doc refusal/conflict alike, and is pinned by five pipeline tests including a gated mid-save host commit (controller.spec:501–525).
- **Badge tri-state + FE-6 generation guard + event retry gated on the doc's ref set** — the “Not configured” lie is gone and the retry path is unit-tested (controller.spec:641–693).
- **Workspace phases and pluralization are real and pinned**: `workspaces.loading/error/empty` gating with the chip suppressed until settled; `.one/.other` singular/plural both asserted.
- **Definition details + edit path** close the remove-and-retype loop with prefill fidelity (blank secrets keep stored values, matching the official `SecretField` contract and the copy in `add.headerSectionHint`).
- **No hardcoded UI text remains** (grep-verified; placeholders, hints, badge states, banners, confirm copy all ride locale keys).

## Prioritized actions

1. **R2U-01 — unblock validation feedback** (reveal problems on touch/blur, or keep Save enabled and set `attempted` on the click; add an invalid-draft render test). This is the cheapest fix with the largest first-run impact.
2. **R2U-02 — make failure copy truthful**: “your change was not saved / the list now shows the current state”, drop the “elsewhere” attribution, and surface `overwrittenRefs` when a pre-configured credential kept the new literal.
3. **R2U-04 + R2U-03 — finish the focus/feedback contract**: focus hand-off after remove and on form close, dialog semantics + Esc for the remove-confirm, and failure feedback near the failing row (scroll-into-view + dismiss).
4. **R2U-05 — stop draft-destroying switches** while a staged form is open.
5. **R2U-06 / R2U-07 — degraded-state affordance and copy nits** (Clear “clearing” label, badge retry, note hoisting, zh ellipsis).
6. **R2U-08 — test hardening** for the new flows (transient dismissal, disabled-submit gate, remove focus, locale-key assertions).
