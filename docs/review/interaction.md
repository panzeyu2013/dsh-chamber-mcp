# Interaction/UX review — MCP servers settings section (`mcp-scope`)

Reviewer: interaction/UX subagent. Scope: browser half of `dsh-mcp-scope`
(`src/client/*`, tests `tests/client/*`), grounded in the actual component
code, locale dictionaries, controller pipelines, the jsdom render suite, and
the official-settings patterns recorded in `docs/recon/ui-contracts.md` §3–5.
Every string is cited by its `mcp-scope.settings` locale key; dictionary
sources: `src/client/locales.ts` (en/zh mirror, key sets asserted equal by
`tests/client/locales.spec.ts`).

Evidence baseline: `node node_modules/vitest/vitest.mjs run
tests/client/section-render.spec.tsx` → **3/3 pass** (jsdom). Component code
contains **no runtime imports from `@deepseek-ai/*`** at all — every control
is hand-written HTML + inline styles; the one CSS-variable use is
`var(--text-2, #555)` in `server-card.tsx:72`.

---

## Summary verdict

The interaction architecture is sound at the domain level: staged draft,
secrets-before-document write order with abort on partial secret failure
(`controller.ts:424–455`), revision-fenced single mutation with automatic
re-sync on conflict (`controller.ts:470–483`), forward-error mapping to
localized banners (`section.tsx:60–71`), real live-update wiring with proper
disposers (`index.ts:109–128`, `controller.ts:311–320`), and solid a11y
fundamentals (htmlFor/id pairs, native `role="switch"` checkboxes, `type=
"button"` everywhere, `role="alert"` on errors). But the **user-visible layer
is where the feature will be judged, and it currently under-communicates at
almost every boundary**: there is no explicit success signal for any action
(add success silently unmounts the form and appends a card that may be below
the fold); cancellation after a partially-failed save silently orphans stored
secrets; error banners render once at the section top, far from the card that
failed; the only per-action pending feedback is "button disabled"; and three
copy defects (`add.argAdd` reused for env/header rows, `server.remove` reused
for row deletes, un-pluralized English counts such as "Off in 1 workspaces")
undercut otherwise careful bilingual copy. Higher-level gaps: server cards
never display the command/URL after add, and there is no edit path other than
remove-and-re-add (which forces retyping write-only secrets); and the
credential badge has no "unknown/loading" state, so a describe failure makes
a *configured* secret read as "Not configured" indefinitely.

Verdict: **functional and structurally sound, not yet release-grade
interaction**. The table below is ordered roughly by user impact.

## Findings

| ID | Sev | Location + evidence | Why it's a problem | Suggested fix |
|---|---|---|---|---|
| UX-01 | **High** | **No success signal + new card lands off-screen.** Add success = form unmounts (`add-form.tsx:254–256 onClose`), server appended to the *end* of the list (`controller.ts:378` `servers: [...base.doc.servers, input.server]`), and `report(outcome)` on ok only clears the error notice (`section.tsx:80–82`) — nothing announces success, no scroll, no focus move, no aria-live. | The only user-visible confirmation of a successful add is the card appearing at the bottom of the server list. With several servers, or a tall per-workspace list inside the card above it, the new card is below the fold and the user sees… nothing happen. Remove and toggle at least change what the user is looking at; add does not. | After a successful add, scroll the new card into view and move focus to its header (or flash a positive note). Same for remove: after the confirm unmounts the card, move focus to the section header/Add button instead of dropping to `<body>`. |
| UX-02 | **High** | **Cancel after a failed save orphans stored secrets, silently.** `submitPlan` (`controller.ts:435–445`) writes staged secrets one-by-one; on any rejection it returns `secret-write-failed` with partial writes already landed and the doc untouched. Conflict (doc write) fails after *all* secrets landed. In both cases the form stays open (`add-form.tsx:253–258`); if the user then presses Cancel (`onClose`, `add-form.tsx:483–485`), the staged refs are dropped with **no cleanup of the literals that were already stored** — they are referenced by no server, visible nowhere (badge list derives from doc refs, `controller.ts:347`), and persist until someone overwrites the same ref. | A user who "cancels" believes nothing was saved. In reality a credential literal (possibly a real API token) remains stored in the credentials domain with zero UI trace, and no copy anywhere explains it. Privacy/mental-model trap, not just tidiness. | Track which refs a save actually wrote before failing; on form Cancel, best-effort `unset` any staged ref not referenced by the current doc (mirror of `unsetQuietly`). At minimum, `secret-clearHint`-style copy on the error banner telling the user partial values may remain stored if they cancel. |
| UX-03 | **High** | **Error feedback renders once at the section top, out of view of the failing action.** All outcomes surface through one notice under the section header (`section.tsx:131–136`) regardless of origin: toggle/remove/Clear failures originate inside a card that, with many workspaces, can be thousands of px below it. | A sighted user toggling a bottom card sees a stale checkbox and, if they don't scroll to the top, never sees `error.conflict`/`error.saveFailed`. `role="alert"` helps screen readers only. | Render outcome feedback at the card/form that triggered it (per-card error line), or `scrollIntoView`+focus the notice when it appears. |

| UX-06 | **Med** | **`add.argAdd` ("Add argument") labels the add-row buttons of the env and header sections** (`add-form.tsx:388–390` env rows, `461–466` header rows — only the args list at `343–345` is a real use); zh mirror `'添加参数'`. | UX-08 | **Med** | **Credential badge has no unknown/loading state; describe failures are swallowed.** Initial `derive()` keeps `EMPTY_CREDENTIALS` until the first describe resolves (`controller.ts:267, 485–497`), and every failure path in `refreshCredentials` is an empty `catch {}` (`controller.ts:366–369`) — badges stay stale with the comment admitting it. The badge then renders `secret.unset` ("Not configured") whenever `view?.configured !== true` (`server-card.tsx:103–109`). | UX-10 | **Med** | **Per-card workspace rows: no collapse, no sort, no grouping; scaffolding repeats per card.** Every card renders one row per workspace unconditionally (`server-card.tsx:132–153`), plus the same two default notes per card (`server.defaultOn` 128, `server.newWorkspaceDefault` 156). ## What is done well (verified, not assumed)

- **Copy discipline**: every rendered string goes through `t()`; en/zh key sets are compile-checked at the register site and asserted equal by `tests/client/locales.spec.ts`; interpolation `{name}`/`{count}`/`{refs}` used consistently. (The two hardcoded placeholders, UX-07, are the single violation.)
- **Secrets architecture**: staged literals never enter the settings doc or ride a response (`add-form.tsx:5–6` comment, `draftToServer` splits secrets out at `136–171`); secrets are written before the doc mutation with abort-on-failure (`controller.ts:424–455`), matching the official `CardSecretSpec` write-outside-the-section pattern (ui-contracts §3) and `SecretField`'s blank-keeps-stored semantics, which the header hint (`add.headerSectionHint`) mirrors.
- **Correctness-first flow**: whole-array atomic `set ['servers']` + per-(ws,server) override ops (`controller.ts:112–167`); revision-fenced mutate with automatic refresh on conflict and accurate conflict copy (`error.conflict` "changed elsewhere; review them and try again") — plus `decodeDoc` hardening so a malformed wire snapshot can't crash the section (`controller.ts:51–63`).
- **Cascade honesty**: the removal confirm states exactly what will happen, including the credential cascade (`server.removeConfirmBody`), and the cascade is executed post-commit, best-effort (`controller.ts:451–468`).
- **Mental model rendering**: default-on is stated twice at the right granularity — `server.defaultOn` above the rows ("On by default unless turned off here") and `server.newWorkspaceDefault` under them, making both per-workspace and future-workspace semantics explicit; empty states exist for no-servers and no-workspaces; the off-count chip keys scanning.
- **Live updates wired and disposable**: `scope.subscribe` + forwarded `settings/document-updated` (ns-filtered) and `credentials/reference-updated` events all registered in one effect whose disposer tears everything down (`index.ts:109–128`, `controller.ts:311–320`); describe failure deliberately cannot break the section (though see UX-08).
- **A11y fundamentals**: labels tied via `htmlFor`/`id` (`server-card.tsx:138–148`; `Field`, `add-form.tsx:195–209`); toggles are native checkboxes with `role="switch"` (state conveyed natively, no custom widget); all buttons explicit `type="button"`; row inputs carry aria-labels; error notices use `role="alert"`; `autoComplete="off"` on text fields and `new-password` on secret inputs; read-only state disables controls rather than hiding the whole surface.
- **jsdom render suite passes 3/3** and pins key copy through locale seats — a working baseline for adding the regression assertions proposed above (UX-05).

## Prioritized actions

1. **Add a real success/pending/failure feedback pass (UX-01, UX-03, UX-09)**: scroll-to-card + focus after add; per-card outcome text; consistent "working" indication for toggle/remove/clear (add form already models it with `state.saving`).
2. **Close the orphan-secret hole (UX-02)**: cleanup of staged-but-unreferenced refs on Cancel after a partial/failed save.
3. **Copy fixes (UX-05, UX-06, UX-07)**: pluralization keys, distinct add/remove-row keys, localized labels/placeholders for env/header rows — plus render-test assertions guarding each.
4. **Show config on cards and close the remove-and-retype loop (UX-04)** — at minimum render command/URL; ideally a real edit path reusing the staged form.
5. **Badge tri-state + retry (UX-08)** so "Not configured" never lies about a configured secret.
6. **Cross-server ref sharing note (UX-11)**, then the smaller polish items (UX-10 collapse, UX-12–UX-19).
